POLICIES / PRIVACY

Privacy policy

Last updated 13 October 2026

This policy describes the information handling visible in the portfolio and storefront code. The storefront needs a configured API and database. A deployment can add services or logging that are not defined in this repository.

Who operates the site

The site identifies its operator as Vikash. The repository does not identify a registered business name, postal address, hosting provider, database host, or a specific privacy-law jurisdiction. You can contact the operator at vikash.e404@gmail.com.

Information you provide

  • Contact message: the portfolio form prepares an email in your email application. The portfolio does not submit that form to its API. Your email application and email provider handle the message after you choose to send it.
  • Store account: registration asks for a name, email address, username, password, and optional access code. The API hashes account passwords before writing them to the user database. Login sends the identifier and password to the API for authentication.
  • Orders: the order API accepts shipping and optional billing addresses, a contact number, optional email, selected payment method, notes, and the products and quantities in the order.
  • Custom requests: the storefront form asks for a title, category, specifications, and optional budget, timeline, and reference links. It is submitted to the configured API.

How information is used

The API uses account information to create and authenticate accounts, and order or request details to operate the corresponding store workflows. If outgoing email is enabled by the operator, the application can send account and order messages through a configured SMTP service. The repository does not identify which email provider is used in a live deployment.

The application records registration, sign-in, and sign-out events in its system log. These records can include an account identifier, an email address or login name, the request IP address, and browser user-agent. A custom request is also written to that log with the signed-in account identifier, the submitted project details, the request IP address, and browser user-agent. The repository does not specify how long these records are kept. Hosting and network logs depend on the deployment provider.

Browser storage and outside services

The storefront stores an access token, account profile, and cart in your browser's local storage. Signing out removes those values. Local storage persists between visits until it is cleared or the application removes it. The admin page also stores its access token in local storage.

The admin page loads fonts from Google Fonts and icons from cdnjs. Store catalog entries can load images from external product or image hosts, including vendor sites, Wikimedia, Unsplash, and a Flaticon fallback. When a browser loads these assets, it connects to the relevant provider and sends ordinary request information such as its IP address. The providers' own policies apply to their services.

The inspected repository contains no analytics integration or first-party code that writes cookies. This does not describe behavior added by a hosting provider, browser, or third-party service.

Storage, retention, and security

Account, order, custom-request, and application-log data are handled by the configured API and MySQL database. The repository does not set a retention period or automatic deletion schedule. The operator's database, log, and backup practices determine how long records remain.

The account service hashes passwords before storing them. Browser access tokens are stored in local storage, which can be read by scripts running on the same site. Sign out when using a shared device. These measures do not guarantee that the application or a deployment is fully secure.

Your choices and requests

You can ask the operator to access, correct, or delete information associated with you, or to close a store account, by emailing vikash.e404@gmail.com. Some order or security records may need to be retained where required to operate the service or comply with applicable law. Rights and response requirements depend on your location and the deployed service.

Payments

The storefront includes a payment-method selection, but the repository does not identify a payment processor. Do not enter card details or payment credentials into these pages. Confirm payment instructions directly with the operator before sending money.

Changes and contact

This page may change when the site or its data practices change. For privacy questions or requests, email vikash.e404@gmail.com.
